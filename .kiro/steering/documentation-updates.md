# 文档与更新记录规范

本项目的每次更新都必须同步维护 GitHub 仓库文档。完成任务前必须执行以下步骤：

1. 根据实际变更更新 `README.md` 或 `docs/` 中相关的使用、配置、部署或维护说明，确保文档与当前行为一致。
2. 更新根目录 `CHANGELOG.md`，使用 `YYYY-MM-DD` 日期标题，最新日期排列在最前。
3. 同一天的多次更新归入同一日期标题，以独立条目准确记录更新模块和具体内容，不使用“优化”“修复问题”等缺少信息的模糊描述。
4. 更新 `README.md`“更新记录”章节中的最新日期和摘要，使仓库首页能够直接看到最近一次更新。
5. 提交前检查代码、相关文档、README 最新摘要和 CHANGELOG 记录是否一致；不得只提交代码而遗漏文档记录。
6. 完成必要验证后，将代码和文档放在同一次提交中并推送到当前 GitHub 分支；除非用户明确要求暂不提交或暂不推送。

纯讨论、信息查询和没有产生仓库文件变更的任务不需要新增更新记录。
